# Security Hardening PR 후속 문서

## 개요
이 문서는 다음 커밋의 변경사항을 기준으로, 보안 강화 목적/적용 범위/검증 포인트를 정리한 후속 문서입니다.

- 커밋: `43cbc2e`
- 제목: `Security hardening: disable VM file sharing, enforce block-file-sharing filter, terminal IP validation, External SSL feature, password policy and setup improvements`

또한 코드 리뷰 과정의 인라인 코멘트 대응 원칙(기능 경계 명확화, 입력 검증 강화, 운영 영향 최소화)을 반영하여 점검 항목을 명시합니다.

---

## 1) VM 파일 공유 경로 차단

### 목적
- VM 콘솔/게스트 채널을 통한 비의도적 파일 반출입을 억제합니다.

### 적용 내용
- SPICE 파일 전송/복사-붙여넣기 관련 플래그를 실행 경로에서 비활성화합니다.
- VM 정적 데이터 구성 시에도 파일 공유 관련 설정이 재활성화되지 않도록 방어 로직을 적용합니다.

### 점검 항목
- Run VM / Run Once 경로에서 관련 플래그가 항상 `false`인지 확인
- UI 모델에서 사용자가 해당 옵션을 우회 설정할 수 없는지 확인

---

## 2) VM 간 파일 공유 차단(디스크/네트워크)

### 목적
- Shareable disk 및 네트워크 필터 누락으로 인한 VM 간 데이터 이동 통로를 최소화합니다.

### 적용 내용
- 디스크 추가/연결/수정 커맨드에서 shareable 디스크를 거부합니다.
- `block-file-sharing` 네트워크 필터를 기본/강제 필터로 설정합니다.
- 기존 vNIC 프로파일에 대해 DB 업그레이드 스크립트로 필터를 일괄 보정합니다.

### 점검 항목
- 신규/수정 vNIC profile 저장 시 mandatory filter가 강제되는지 확인
- DB 업그레이드 후 기존 프로파일에 필터가 반영됐는지 확인
- UI에서 shareable 체크박스가 비활성화/비노출인지 확인

---

## 3) Terminal IP 인증 입력 검증 강화

### 목적
- CIDR/범위 입력을 차단하고 단일 IPv4 주소만 허용하여 정책 해석 모호성을 제거합니다.

### 적용 내용
- 서버 유틸리티에서 단일 IPv4 패턴 검증을 적용합니다.
- 클라이언트 UI에서도 동일 제약을 적용해 조기 피드백을 제공합니다.
- 커맨드 실패 시 사용자에게 원인 메시지를 전달합니다.

### 점검 항목
- `192.168.0.10` 허용, `192.168.0.0/24` 거부
- 유효하지 않은 포맷 입력 시 서버/클라이언트 모두 실패 처리 일치

---

## 4) 외부 SSL 적용 워크플로

### 목적
- 운영자가 외부에서 발급받은 인증서/키/CA 체인을 UI 기반으로 안전하게 반영할 수 있게 합니다.

### 적용 내용
- `ApplyExternalSsl` 액션/파라미터/백엔드 커맨드를 추가합니다.
- 보안 설정 화면에 업로드 UI를 추가하고 인증서/키/CA 본문 전달을 구현합니다.

### 운영 시 유의사항
- 업로드 파일 포맷(PEM)과 체인 순서 검증 필요
- 키/인증서 불일치 시 명확한 오류 메시지 필요
- 적용 후 관련 서비스 재시작/상태 점검 절차 문서화 필요

---

## 5) 비밀번호 재설정 정책 강화

### 목적
- 약한 비밀번호 설정을 방지하고 서버-클라이언트 정책 불일치를 줄입니다.

### 적용 내용
- 서버에서 복잡도 검사를 강제합니다.
- UI에서도 동일한 조건(길이/대소문자/숫자/특수문자)을 검증합니다.

### 점검 항목
- 정책 미충족 비밀번호가 서버에서 반드시 거부되는지 확인
- UI 문구와 실제 서버 정책이 일치하는지 확인

---

## 6) 리뷰 코멘트 대응 체크리스트

아래 항목은 인라인 코멘트에서 반복적으로 요구되는 품질 기준을 기준으로 정리한 것입니다.

- 기능 강제(enforcement)가 UI 레벨이 아닌 서버 레벨에서도 보장되는가?
- 동일 정책이 UI/서버/DB 마이그레이션 전 구간에서 일관적인가?
- 실패 시 사용자/운영자 관점의 에러 메시지가 충분히 구체적인가?
- 업그레이드 경로(기존 데이터)까지 포함하여 보안 정책이 적용되는가?
- 테스트(단위/통합)에서 정상/비정상 케이스가 모두 커버되는가?

---

## 7) 권장 추가 작업

1. External SSL 커맨드 단위 테스트 추가
   - 인증서/키 매칭 실패, CA 체인 누락, 빈 입력 등 부정 케이스 보강
2. vNIC 필터 강제 정책 통합 테스트
   - 신규 생성 + 기존 데이터 마이그레이션 이후 재수정 시나리오 검증
3. 비밀번호 정책 메시지 i18n 정합성 점검
   - 언어별 메시지와 실제 정책 조건 문구 일치 여부 확인
4. 운영 문서 보강
   - 보안 설정 변경 후 롤백 절차/장애 대응(runbook) 추가

---

## 8) 결론
본 PR은 VM 파일 공유 경로 차단, 네트워크/스토리지 통로 제어, 입력 검증 강화, 외부 SSL 적용성, 비밀번호 정책 강화 측면에서 보안 수준을 전반적으로 상향합니다.

후속으로는 테스트 범위를 넓혀 회귀 리스크를 줄이고, 운영 문서(runbook)와 오류 메시지 가독성을 개선하면 실제 운영 안정성이 더 높아집니다.
