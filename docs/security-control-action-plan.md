# 보안 요구사항 이행 방안 (운영/시험 절차 포함)

본 문서는 요청된 9개 보안 요구사항에 대해 **운영 적용 방법**, **감사기록 처리 방법**, **자체 시험 절차**를 제시합니다.

## 1. 인증 실패 대응

### 1.1 5회 인증 실패 시 계정 잠금/해제
- **정책**: 동일 계정 연속 인증 실패 5회 발생 시 계정을 잠금 처리합니다.
- **잠금 시간**: 기본 30분 자동 해제(권장) 또는 관리자 수동 해제.
- **관리자 해제 방법**
  1. 관리자 콘솔에서 사용자 상태 확인
  2. 잠금 해제(Unlock) 실행
  3. 해제 사유(오입력, 사용자 요청, 공격 대응 등) 기록

### 1.2 인증 실패 감사정보 기록/확인
- **기록 항목**: 계정명, 원본 IP, 실패 시각, 실패 사유(비밀번호 오류/잠금 계정), User-Agent, 실패 누적 횟수.
- **확인 경로**
  - 관리자 포털 감사 로그 화면
  - DB `audit_log` 조회
  - `/var/log/ovirt-engine/engine.log` 검색
- **권장 감사 이벤트 예시**
  - `USER_LOGIN_FAILED`
  - `USER_ACCOUNT_LOCKED`
  - `USER_ACCOUNT_UNLOCKED`

---

## 2. 인증 정보 재사용 방지

### 2.1 세션 ID 타임아웃(10분)
- **정책**: 마지막 요청 후 10분(`600s`) 무활동 시 세션 만료.
- **적용 위치**
  - SSO/세션 관리 설정
  - 웹 애플리케이션 세션 타임아웃 설정
  - 리버스 프록시(사용 시) idle timeout과 정합성 유지
- **보안 요구사항**
  - 재로그인 시 **새 세션 ID 발급**
  - 로그아웃/만료 시 세션 즉시 폐기
  - 세션 쿠키에 `HttpOnly`, `Secure`, `SameSite` 적용

---

## 3. 보안관리 기능 (감사기록 조회)

- **기능 요구사항**
  - 기간/사용자/이벤트 유형/IP 기준 필터링
  - CSV/JSON 내보내기
  - 관리자 권한 분리(조회 전용, 운영 관리자)
- **운영 절차**
  1. 일일 점검: 인증 실패 급증, 잠금 이벤트, 정책 변경 이벤트 확인
  2. 주간 점검: 상위 실패 IP, 야간 관리자 로그인, 비정상 패턴 분석
  3. 월간 보고: 요약 통계와 조치 내역 문서화

---

## 4. 보안기능 자체 시험

### 4.1 수행 조건
- **주기적 시험**: 월 1회
- **수시 시험**: 관리자 요청 시 즉시 수행

### 4.2 시험 대상
- 인증 실패 잠금 기능
- 세션 타임아웃(10분)
- 감사기록 생성/조회/보존
- 관리자 해제 기능

### 4.3 시험 방법(세부 절차)
1. 테스트 계정 생성(일반 사용자/관리자)
2. 동일 IP에서 의도적으로 5회 인증 실패 수행
3. 계정 잠금 이벤트와 감사기록 생성 여부 확인
4. 관리자 계정으로 잠금 해제 수행 후 해제 감사기록 확인
5. 정상 로그인 후 10분 무활동 유지
6. 세션 만료 및 재접속 시 새 세션 ID 발급 여부 확인
7. 결과를 시험 결과서(일시/담당자/증적 캡처/판정)로 보관

### 4.4 기술 적용 방법
- 자동화 스크립트(예: curl + API, Selenium/Playwright)로 반복 재현
- 로그 수집기(SIEM/syslog)와 이벤트 상호 대조
- 실패 시 티켓 자동 발행(운영관리 시스템 연동)

## 5. 무결성 검증

### 5.1 검증 대상
- 애플리케이션 바이너리/JAR
- 설정 파일(인증/세션/감사정책)
- 감사로그 파일 및 백업본

### 5.2 검증 절차
1. 기준시점 해시(SHA-256) 생성 및 안전 저장
2. 정기 배치(일 1회)로 대상 파일 재해시
3. 기준 해시와 비교해 변경 탐지
4. 무결성 불일치 시 즉시 경보 및 변경 승인 이력 대조
5. 비인가 변경이면 서비스 격리/롤백/사고 대응 절차 착수

### 5.3 시험 방법/기술 적용
- 파일 무결성 도구(AIDE, sha256sum 스크립트)
- CI/CD 배포 아티팩트 서명 검증
- DB 감사 설정값은 쿼리 스냅샷 비교로 변조 여부 확인

---

## 6. 세션 잠금 종료 기능

### 6.1 세션 잠금 해제 방법
- **자동 해제**: 정책 시간 경과 시 자동 해제
- **수동 해제**: 관리자 콘솔/API에서 특정 계정 세션 강제 종료 + 잠금 해제

### 6.2 감사기록 저장
- 필수 기록: 대상 계정, 수행 관리자, 해제 시각, 해제 사유, 수행 채널(UI/API)
- 이벤트 예시
  - `USER_SESSION_LOCKED`
  - `USER_SESSION_UNLOCKED`
  - `USER_SESSION_TERMINATED_BY_ADMIN`

---

## 7. 감사기록 생성 (단말 접속 IP 차단)

- 방화벽/접근제어에서 IP 차단 발생 시 아래를 감사로그로 남깁니다.
  - 차단 대상 IP, 차단 룰 ID, 차단 시각, 탐지 근거(실패 횟수/평판/수동차단), 처리 주체
- 네트워크 장비/OS 로그와 애플리케이션 감사로그를 **상호 연계 ID**로 매핑해 추적성을 보장합니다.

---

## 8. 감사기록 손실 예측 시 대응행동

### 8.1 스토리지 용량 임계치 대응
- **임계치 기준 예시**
  - 70%: 경고(용량 증설 계획 수립)
  - 85%: 심각(보관주기 점검, 압축/아카이빙 실행)
  - 95%: 비상(원격 저장소 즉시 전송, 불필요 로그 정리 승인 절차 수행)

### 8.2 운영 행동
1. 모니터링 알람 수신
2. 로그 로테이션/압축 강제 실행
3. 원격 백업 저장소로 우선 전송
4. 장애 전파(보안/인프라/서비스 담당)
5. 손실 위험 해소 후 재발방지 대책 등록

---

## 9. 감사기록 손실 방지 (저장 실패 대응)

- **저장 실패 감지**: 로거 에러, 디스크 I/O 에러, DB Insert 실패 이벤트 모니터링
- **즉시 조치**
  1. 로컬 버퍼/큐(예: rsyslog queue)로 임시 적재
  2. 원격 로그 서버 이중화 경로로 재전송
  3. 저장 복구 후 누락 구간 재처리(replay)
- **설계 권고**
  - 최소 2개 저장 경로(로컬 + 원격)
  - 감사로그 전용 파티션 운영
  - 실패 이벤트 자체도 별도 채널로 알림(메일/메신저/티켓)
