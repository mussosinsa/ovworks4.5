## 1. 기능 개요

### 1.1 패스워드 리셋 기능

패스워드 리셋 기능은 관리자가 사용자의 패스워드를 강제로 재설정할 수 있는 관리 기능입니다. 보안 사고 대응, 사용자 패스워드 분실 시 복구 등의 상황에서 사용됩니다.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          사용자 관리 화면 구성                                │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  경로: 관리 > 사용자                                                         │
│                                                                             │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  users:type = user    [x] [☆] [▼] [Q]      [패스워드 리셋] [태그 설정] │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  ┌──────────┬──────────┐                                                   │
│  │ [사용자] │   그룹   │                                                    │
│  └──────────┴──────────┘                                                   │
│                                                                             │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  이름   │  성  │ 사용자 이름 │ 인증 공급자     │ 네임스페이스 │ 이메일   │   │

│  │ ▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲│   │
```

### 1.3 주요 기능

| 기능 | 설명 |
|------|------|
| 패스워드 리셋 | 관리자가 사용자의 패스워드를 새로운 값으로 설정 |
| 패스워드 정책 검증 | 설정된 보안 정책에 따라 패스워드 강도 검증 |
| 감사 로그 | 모든 패스워드 변경 시도 기록 |
| 유효 기간 설정 | 새 패스워드의 유효 기간 자동 설정 (10년) |

> **패스워드 재사용 정책 범위:** WebAdmin과 BLL은 패스워드 이력을 저장하거나 이력의 생성 시각을 비교하지
> 않습니다. 패스워드 변경은 `ovirt-aaa-jdbc-tool user password-reset`에 위임되며, 도구가 이력 위반을
> 반환한 경우에만 해당 오류를 사용자에게 전달합니다. 따라서 현재 구현만으로는 "3개월 이내 사용된
> 패스워드 재사용 금지" 준수를 보장할 수 없습니다.

| 오류 상황 | 메시지 |
|----------|--------|
| 패스워드 미입력 | 패스워드 변경에 실패했습니다. |

| 대문자 누락 | 패스워드에 대문자가 포함되어야 합니다. |
| 소문자 누락 | 패스워드에 소문자가 포함되어야 합니다. |
| 숫자 누락 | 패스워드에 숫자가 포함되어야 합니다. |
| 특수문자 누락 | 패스워드에 특수문자가 포함되어야 합니다. |
| AAA 공급자가 이전 패스워드 재사용을 거부 | 이전에 사용한 패스워드는 사용할 수 없습니다. |

| 사용자명 포함 | 패스워드에 사용자 이름이 포함될 수 없습니다. |
| 정책 미충족 | 패스워드 정책을 충족하지 않습니다. |

## 3. 보안 구현 명세서

### 3.0 3개월 이내 패스워드 재사용 금지 검토 결과

현재 엔진 구현의 판정은 **미구현**입니다.

* `ResetUserPasswordCommand`는 길이, 대문자, 소문자, 숫자, 특수문자 및 사용자명과의 동일 여부만 직접
  검사합니다.
* 엔진 DB에는 이전 패스워드 해시와 변경 시각을 저장하지 않으며, 최근 3개월 구간을 계산하는 코드도
  없습니다.
* `ovirt-aaa-jdbc-tool` 출력에 `history` 또는 `previously used`가 포함되면 오류 문구를 변환하지만, 이는
  공급자가 이미 거부한 결과를 표시하는 처리일 뿐 3개월 이력 정책을 구현한 것이 아닙니다.
* `ENGINE_PASSWORD_HISTORY_SIZE`는 이 저장소에서 읽거나 적용하는 엔진 설정이 아니므로 이를 설정 파일에
  추가해도 3개월 재사용 금지가 활성화되지 않습니다.

준수 판정을 위해서는 사용하는 AAA-JDBC 버전이 제공하는 실제 패스워드 이력 정책을 먼저 확인하고,
동일한 패스워드를 즉시 및 3개월 경계 전후에 다시 설정하는 통합 시험을 수행해야 합니다. 공급자가
기간 기반 이력을 제공하지 않으면 변경 시각과 안전한 이전 해시를 보관하고 3개월 범위를 검사하는 별도
서버 측 구현이 필요합니다. 평문 패스워드를 엔진 DB나 로그에 저장해서는 안 됩니다.
